# 07 · AI-tells 黑名单与替代做法

这是本 skill 的心脏。**写码前读一遍，交付前用 `scripts/audit.mjs` 复核。**

判定原则：一个特征之所以是 tell，不是因为它本身丑，而是因为它**与简报无关地、无差别地出现在任何主题上**。所以黑名单永远有例外——例外必须来自简报。

---

## A. 视觉与 CSS

### A1 统一圆角
**Tell**：`border-radius` 全局一个值，卡片/按钮/输入框/头像全一样；或所有元素都用 `16px`。
**为什么**：圆角是层级信号。容器、控件、徽标使用同一半径，等于放弃了层级表达。
**替代**：至少三级半径刻度（如 `--r-sm: 4px / --r-md: 10px / --r-lg: 22px`），容器最大、控件最小、徽标用 `999px`。或全站锐角（`0`），但必须是决定，不是遗漏。

### A2 同款柔和阴影
**Tell**：`box-shadow: 0 1px 3px rgba(0,0,0,.1)` 出现在所有卡片上。
**为什么**：真实的光照有方向、有距离衰减、有颜色。同一团灰雾贴在每张卡下面说明它是装饰。
**替代**：阴影与层级绑定（浮层最深、卡片最浅、静态面板无阴影改用描边）；阴影带方向与色偏，如 `0 8px 24px -12px hsl(220 40% 12% / .35)`；或改用 1px 描边 + 背景明度差来表达层次。

### A3 `#0B0B0B` 冒充纯黑
**Tell**：`#0B0B0B` / `#111` / `#0f0f0f` 作为"高级黑"，配一个高饱和强调色。
**为什么**：这是一个已成簇出现的默认配方，出现在 SaaS、作品集、AI 工具页上。
**替代**：黑要带明确色相与语境（深墨蓝 `hsl(220 45% 8%)`、深褐 `hsl(28 30% 9%)`），或干脆用真正的 `#000` 并靠材质与排版制造层次。

**真 `#000` 的正确用法**：纯黑底板显露廉价感的地方不是"黑"，而是"什么都没有"。不要靠调亮底色来解决——在黑底上压一层**环境光**，一到两条极淡的径向光带，画面立刻有空间：

```css
.plate {
  background:
    radial-gradient(130% 55% at 50% 82%, hsl(212 64% 30% / .14), transparent 72%),
    radial-gradient(70% 38% at 16% 10%,  hsl(28 52% 34% / .08), transparent 70%),
    #000;
}
```

**量级是这一条的成败所在**：重一点就从"有空间"变成"糊了一块脏色"。加完用 `scripts/measure.mjs` 量一次——中位亮度应当仍落在 5–30 且 p95 不变；若中位被推过 30，说明光带已经改变了整体明度，**收 alpha，不要收面积**（面积决定空间感，alpha 决定它有多脏）。

光带方向必须与页面其他光影同源，位置落在内容下方或背后，不要压在正文上。检索引出的深色方案若自带 `Card` / `Muted` 明度阶，优先用那一套表达空间，光带只是补充。

### A4 渐变洗色
**Tell**：`linear-gradient(135deg, #667eea, #764ba2)` 作背景装饰；按钮也都带渐变。
**替代**：渐变只在其承载意义时使用（深度、光照、数据映射、状态过渡），且与色板同源。装饰性背景优先用：纯色 + 噪点、细网格、纸纹、单一强调色块。

### A5 三段式卡片同构
**Tell**：所有内容都被切成同宽同高的圆角卡片，卡内结构也一样：图标 + 标题 + 两行描述。
**替代**：按内容形态选容器——长文本用版心列、数据用表格、并列项用带分隔线的列表、重点用整幅色块。**同一页面至少两种容器形态。**

### A6 z-index 暴力堆叠
**Tell**：`z-index: 9999`、`99999`。
**替代**：建立明确的层级表（`--z-base: 0 / --z-sticky: 10 / --z-overlay: 20 / --z-modal: 30 / --z-toast: 40`），只允许使用表内值。

### A7 `width: 100vw` 引起横向滚动
**Tell**：`width: 100vw` 在有滚动条的页面造成溢出。
**替代**：`width: 100%`，或 `100dvw` 配合 `overflow-x: clip`；溢出内容用 `overflow-x: auto` 的滚动容器承载。

## B. 排版

### B1 单字强调
**Tell**：`这是<em>唯一</em>的重点` —— 标题里一个词换色/斜体/加粗。
**为什么**：最常见的生成痕迹，且几乎不承载信息。
**替代**：整句统一处理；若真要强调，用排版层级（更大字号、独占一行）、留白、或与该词意义相关的视觉手法（如一个数字就用巨型数字）。

### B2 全大写 + 大字距的小标签
**Tell**：`text-transform: uppercase; letter-spacing: .12em` 的 eyebrow，出现在每个标题上方。
**替代**：标签用正常大小写 + 字号/色阶区分；确需全大写时只在一处，并确保它携带分类信息。

### B3 编号装饰
**Tell**：`01 / 02 / 03` 出现在并非序列的内容上。
**替代**：内容真是序列（流程、时间线、步骤）才编号，并让编号携带位置感（进度、当前高亮）。

### B4 行宽与行高失控
**Tell**：正文行宽超过 90 字符；衬线体用小行高；无衬线体行高 1.2。
**替代**：正文行长 45–80 字符（`max-width: 62ch` 左右）；无衬线正文 `line-height: 1.5–1.65`，衬线 `1.55–1.75`；标题行高 `1.05–1.25`。

### B5 字体陈词（默认族）
**Tell**：不加思索地用 `Inter` / `Poppins` / `Montserrat` / `Roboto` / `Playfair Display` / `Space Grotesk` 作主字体。
**替代**：见 `02-aesthetic-directions.md` 的方向配方，每个方向都给了非默认字体对。`Inter` 只在需要极致中性时使用，并明确说得出为什么。

## C. 布局与间距

### C1 居中 + 三卡片 + 大标题
**Tell**：Hero 居中大标题 + 副标题 + 两个按钮，随后三段式特性区。
**替代**：让首屏呈现主体世界里**最有特征的那一样东西**——一个数字、一张图、一次交互、一段真实产品的切片。三卡片只在内容确实并列三项时使用。

### C2 无差别入场动画
**Tell**：每个 section 都 `fade + translateY(20px)` 入场；每张卡 hover 都上移 4px。
**替代**：一处编排好的入场（一次揭开、一次序列），其余静止；交互反馈只在用户动作发生时出现，且说明"什么变了"。见 `04-motion.md`。

### C3 间距无刻度
**Tell**：`margin: 37px`、`padding: 13px` 之类的随手值。
**替代**：8pt 刻度（`4 8 12 16 24 32 48 64 96 128`）或 4pt 细分刻度的 CSS 变量；垂直节奏靠刻度决定，不靠手感。

### C4 分区边界靠背景色交替
**Tell**：一段白、一段浅灰、一段白。
**替代**：用留白、分隔线、字号变化、或整幅强调色块来分区。

## D. 内容与数据（Jane Doe 效应）

- **Tell**：`Lorem ipsum`、`Jane Doe`、`John Smith`、`Acme Corp`、`user@example.com`、`$1,234.56` 全站唯一数字、通用头像。
- **为什么**：内容也是设计材料。假数据会掩盖真实的文字长度、换行、密度问题，而且一眼可辨。
- **替代**：写真实可信的内容——真实的产品名、真实的文案、符合业务量级的数字（真实价格带、真实条数）、带长中短三种长度的名字。人名用多样化的真实名字，不要重复同一形态。

### D2 模板文案语法
- `A · B · C` 用中点拼接的 meta 行
- `WORD — fragment` 空格 + 破折号
- 按钮文案 `Submit` / `Learn more` / `Get started`
- 错误提示 `Something went wrong`
- 标签 `Feature 1`
- **替代**：见 `09-copy.md`。按钮用动词短语明确结果（`Save changes`、`创建项目`）；错误说清发生了什么与怎么修；空态是行动邀请。

### D3 界面里用 emoji 当图标
- **替代**：统一图标集（Lucide / Phosphor / Radix Icons / 自绘 SVG），同一集中的同一风格，尺寸与描边统一。表情只在产品本身以表情为内容时出现。

## E. 外部资源与依赖

### E1 凭空 import
**Tell**：`import { motion } from "framer-motion"` 但项目里没装；或引用不存在的组件路径。
**替代**：**强制依赖验证**——写任何 import 前先确认：读 `package.json` 依赖表、检查 `node_modules/`、或看已有文件的 import 习惯。只在已验证的范围内使用；需要新依赖就明确说出来并说明理由。

### E2 barrel 导入
**Tell**：`import { Button } from "@/components"`。
**替代**：直接指向文件：`import { Button } from "@/components/ui/button"`。减少打包体积与循环依赖，见 `06-engineering.md`。

### E3 未固定的远程资源
**Tell**：引用第三方 CDN 上的字体/脚本/图片却无 fallback、无尺寸、无 `loading` 策略。
**替代**：声明 fallback 字体栈、预留尺寸、`loading="lazy"` + `decoding="async"`，关键资源预连接。

## F. 无障碍与状态（生产级 tell）

| Tell | 替代 |
|---|---|
| `outline: none` 且无替代焦点样式 | `:focus-visible` 给清晰焦点环，且不破坏布局 |
| 有动画但无 `prefers-reduced-motion` 处理 | 媒体查询内降级为即时状态或纯透明度变化 |
| 只用颜色表达成功/失败 | 颜色 + 图标 + 文案三重编码 |
| 空列表渲染空白 | 设计空态：说明 + 一个明确动作 |
| 表单错误只用红色边框 | 边框 + 图标 + 就近的文字说明 + `aria-describedby` |
| 点击区只有文字大小 | 触控目标 ≥ 44×44px（用 padding 扩大热区） |
