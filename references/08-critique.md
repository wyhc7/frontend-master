# 08 · 评审与自检协议

P4 阶段使用，也是六个设计操作符的判定手册。目标：**把"感觉不太对"转成可执行、可复核、可关闭的问题项。** 评审不是表达品味，是产出可关闭的工作项。

---

## A. 铁律：没看渲染结果，不许评审

**没有截图的评审意见一律视为空泛意见，不得进入交付说明。** 看代码只能发现写法问题；构图、层级、重心、留白节奏只在渲染结果里存在——看代码说"层级不够清晰"是猜测，看截图说"`hero.tsx:42` 主副标题字号比 1:1.6，层级没拉开"才是结论。

**截图最小集（5 张，缺一不可）**

| # | 视口 | 尺寸 | 模式 | 必查项 |
|---|---|---|---|---|
| 1 | 移动 | 375×812 | 亮 | 横向滚动、触控目标 ≥44px、首屏是否被压扁 |
| 2 | 移动 | 375×812 | 暗 | 暗模式是否只是反色、边界是否消失 |
| 3 | 桌面 | 1440×900 | 亮 | 重心、留白节奏、容器形态是否 ≥2 种 |
| 4 | 桌面 | 1440×900 | 暗 | 对比度、阴影/描边在暗底是否成立 |
| 5 | 宽屏 | 1920×1080 | 亮 | 正文行长是否超 90 字符、内容是否被拉成空壳 |

**关键断点**：逐个截 CSS 中实际声明的 `@media` 断点，取两侧各一张——断点交界最容易崩，也只截 1440 永远发现不了。**状态矩阵**：空态 / 加载态 / 错误态 / 成功态 / 权限不足各一张，只截有数据的正常态等于没测过这个页面。

**唯一例外**：项目无法构建或运行时允许静态评审，但必须在结论开头写明"未看渲染，仅覆盖 `07-ai-tells.md` 可机械判定的部分"，并标为待复评。

## B. 输出契约：`file:line` 级问题清单

每条必须四项俱全，缺一项即无效：

```
<严重度> <file>:<line> — <问题>
为什么：<破坏了哪条判据，判据出自哪个文件>
修复：<动词开头的具体动作，写清改成什么>

CRITICAL src/app/page.tsx:88 — 卡片 grid 在 375px 溢出 14px，出现横向滚动
为什么：违反 SKILL.md Quality Floor 1，移动端首屏被裁切
修复：grid-template-columns 改为 minmax(0,1fr)，并在 <768px 降为单列

WARN src/components/Stat.tsx:31 — 统计块与容器用同一 --r-md 半径
为什么：命中 07-A1，层级信号被抹平
修复：统计块降到 --r-sm，容器保持 --r-lg
```

**禁止清单（出现即重写该条）**

| 禁止表述 | 为什么无效 |
|---|---|
| 整体感觉不错，可以再优化一下 | 无 position、无判据、无动作 |
| 建议加强视觉层次 | 没说是哪个元素的什么关系 |
| 配色可以更协调 | 没说哪两个色冲突、目标是什么 |
| 这里有点奇怪 | 未定位，不可关闭 |

**可关闭性检验**：把这条交给另一个人，他能否在不问你的情况下改完并判断改对了？不能，就重写这条。

## C. 严重度分级

判定规则一句话：**违反 Quality Floor，或造成功能性失败 → `CRITICAL`（必须修完才能交付，不许保留）；只违背审美准则、不破坏可用性 → `WARN`（要么修，要么在交付说明里给出保留理由，理由必须引用简报原话或锁定的审美方向）。**

**`CRITICAL` 实例**：375px 横向滚动（QF1）· 无可见焦点环（QF2）· 正文对比度 <4.5:1（QF4）· 缺 `alt`/`label`（QF6）· 空态错误态渲染空白（QF10）· `Lorem ipsum`/`Acme`/`example.com` 残留（QF11）· 未安装依赖导致构建失败（QF9）· 图片无尺寸造成 CLS（QF8）· 硬编码色值绕过 P2 token（破坏 P2 契约，无法一致修改）。

**`WARN` 实例**：`margin: 37px`（07-C3）· `z-index: 9999` 但无实际堆叠冲突（07-A6）· 全大写 eyebrow 只在一处且真的在标分类（07-B2 允许由简报背书）· 装饰性渐变但该方向以辉光为语言 · 只用一种容器形态而内容确实同质（07-A5 例外）· 数字未用 `tabular-nums` · 手机号未 `inputmode="tel"`。

**易错的三处边界**

| 判定点 | 结论 |
|---|---|
| 暗模式缺失，或暗模式对比度不足 | `CRITICAL`（QF7 要求消费级页面两模式都测过） |
| 出现 `#0B0B0B` 单独一处 | `WARN`；若同时配高饱和酸绿且全站只此一套配方，升 `CRITICAL`（07-A3 成簇判定） |
| 动效缺 `prefers-reduced-motion` 降级 | `CRITICAL`；动效曲线不好看是 `WARN` |

## D. 与机器审计的分工

P4 有两条**互相独立**的证据，不可互相替代；顺序固定：先机器，后人工。存在 `CRITICAL` 时退出码为 1，输出 `扫描 N 个文件 · CRITICAL n · WARN n`，`--json` 拿结构化结果。

```bash
node ~/.dsh/skills/frontend-master/scripts/audit.mjs <目录或文件...>
```

| 机器管（可判定的） | 人工管（机器判不了的） |
|---|---|
| `a11y/img-alt` `a11y/control-label` `a11y/link-name` `a11y/focus-outline` `a11y/zoom-lock` | 焦点顺序是否符合阅读顺序；可访问名称是否真有信息量 |
| `a11y/click-target` `a11y/emoji-icon` `a11y/html-lang` `a11y/viewport-meta` `a11y/reduced-motion` | 动效降级后是否仍保留"什么变了"的反馈 |
| `content/lorem` `content/placeholder-name` `content/example-domain` `content/acme` `content/foobar` | 文案是否用主体世界的行话；按钮是否说清结果（见 `09-copy.md`） |
| `aitell/hardcoded-hex` `aitell/black-acid` `aitell/violet-gradient` | 色板是否与 `02` 锁定方向一致；强调色是否被摊薄到 5 处 |
| `aitell/uniform-radius` `aitell/uniform-shadow` `aitell/eyebrow` `aitell/hover-shift` | 该例外是否有简报背书；同页容器形态是否 ≥2 种 |
| `perf/img-size` `perf/transition-all` `perf/layout-animation` `perf/font-display` `eng/unverified-dep` | 首屏是否呈现主体世界最有特征的东西；构图意图与层级是否在编码信息 |

**边界规则**

1. 机器能判定的不许再写进人工清单当意见；人工发现可正则化的问题，标注"可机械化"，本轮不改 `audit.mjs`。
2. 结论冲突时以人工为准，但必须给出判定理由（脚本报统一圆角而简报要求"全部锐角"——这是决定而非遗漏，见 07-A1）；审计全绿而截图仍"一眼 AI"，说明缺的是人工那条证据，回 `07-ai-tells.md` 的 A/B/C 三类逐条目视。
3. 改过 `audit.mjs` 规则后必须跑夹具回归：`scripts/selftest/deliberately-bad.html` 期望 `CRITICAL 11 · WARN 14`，`scripts/selftest/clean.html` 期望 0 findings；数值对不上说明规则被改坏。
4. 凡采用检索层（`scripts/data.mjs`）给出的风格或配色，评审时按 SKILL.md 的仲裁规则复核：命中黑名单（Glassmorphism / Claymorphism / Neumorphism / Aurora UI / 紫靛渐变 / 纯黑底+高饱和强调色）的必须有写在提案里的对冲措施，否则记 `WARN` 并要求补写来源记录（哪个 domain、哪条记录）。

## E. 六个操作符的判定标准（一次只下一个，按下表判据收工）

| 操作符 | 触发条件 | 具体改什么 | 到位判据 |
|---|---|---|---|
| `critique` | 说不出问题在哪；评审他人界面；进入 P4 | **只诊断，不改代码**；按 B 契约输出清单，每条标注后续用哪个操作符 | 每条都带 position 与修复动作；没有一条是"整体感觉" |
| `polish` | 结构与内容已定，观感"毛躁/廉价" | 间距回刻度；视觉对齐修正；大字号负字距；表格数字 `tabular-nums`；1px 线在 2x 屏取值 | 相邻间距都能说出属于同一刻度关系；两版截图叠加时主要边界重合 |
| `distill` | 一屏里说不清哪些必要；删掉任一元素都不觉得损失信息 | **删元素，不是缩小元素**：三卡合并成一句；去掉纯装饰层；并列信息收进一个容器；只留一个焦点 | 剩下的每个元素都能辩护"删了会丢信息"；可扫读性上升而信息量不减 |
| `quieter` | 视觉音量超过内容重要性；内容才是主角 | 降饱和度与对比色差；强调色压到 ≤2 处；阴影换描边；动效降到状态反馈；字号跨度收窄 | 缩到 25% 截图仍能分清层级（不是一团灰）；强调色只落在真正的行动上 |
| `bolder` | 什么都"挺好看"但记不住；主体有强材料却没用 | **只放大一个变量**：字号跨度 / 对比 / 色块面积 / 一处破格；同时删掉若干小装饰腾预算 | 闭眼回忆能说出一个视觉锚点；缩到 25% 时存在明确重心块 |
| `delight` | 功能完整但手感死板；动作缺少反馈 | **只加一处**且与动作语义相关（保存→印记、复制→瞬态确认、拖拽→物理跟随）；时长曲线取自 `04-motion.md`；`prefers-reduced-motion` 有降级；不改布局 | 反馈说明"什么变了"而非"发生了"；关掉动效后功能完整且无布局位移 |

**操作符冲突**：`quieter` 与 `bolder` 不相邻施加；`distill` 与 `delight` 不同轮（先删干净再加手感）。冲突时先 `critique`，让清单决定顺序。

## F. 单变量原则

**一次只改一个变量，改完立刻截图复核，与上一版做 diff。** 变量指间距刻度、字号/字阶、色值、容器形态、动效参数、文案；复核循环为：改一个变量 → 重截最小集（至少 1440 亮 + 375 亮）→ 与上一版并排看 → 判据不成立就回滚整个改动，换下一个假设。回滚是正常动作，不是失败。

| 混改症状 | 说明 |
|---|---|
| 说不清哪一处变好了 | 归因失败，无法保留好的部分 |
| 修好 A 又坏了 B | 典型纠缠：同改字号与间距，正文行超 80 字符 |
| token 漂移 | 边改边试新色，页面出现 P2 色板外的第五种灰 |
| 截图 diff 全是噪点 | 布局骨架同时被改，视觉比对失去信息 |
| 反复来回 | 目标互斥的两个操作符同时施加 |

## G. 评审他人 / 竞品界面

| 维度 | 评审自己产出 | 评审他人 / 竞品 |
|---|---|---|
| 证据锚点 | 有源码，落 `file:line` | 无源码时落 `<视口> <区域> <selector 或坐标>` |
| 判据来源 | 与自己 P1 锁定的方向与 DIALS 比 | 与**它自己的受众与用途**比，不按你的品味判 |
| 必做前置 | 复述自己的 Design Read | 先推断它的 Design Read：在尝试做什么、给谁 |
| 输出形态 | 问题清单 + 修复动作 | 问题清单 + 意图推断 + 可借鉴点（≤3 条） |
| 禁止 | 用"感觉"当判据 | 把自己的方向当唯一正确答案；未推断出它意图就断言它错 |

外部评审的 `CRITICAL` 只保留功能性失败（布局崩坏、不可读、不可操作）；审美差异一律记 `WARN` 并注明"这是它的方向选择"；对比方式是与同类并排找差异，不排优劣。

## H. 常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 改完更好看，但更不像这个主体了 | 目标漂移成"通用好看"，丢了主体材料与行话 | 回 `01-design-read.md` E 的三个问题，用主体世界最有特征的东西替换刚加的装饰 |
| 越改越乱 | 一次动多个变量 | 回 F：一次一个操作符，改完截图复核，判据不成立就回滚 |
| 评审意见互相矛盾 | 没有共同判据（方向与旋钮未锁定） | 先复述 Design Read 与 DIALS；按"是否服务于核心用途"裁决；真冲突项升给用户二选一，附两组 token 对比 |
| 意见全是"感觉再调调" | 没看渲染结果 | 执行 A 的截图协议，重写清单 |
| 机器审计全绿但页面仍像 AI | 用工具代替视觉复核 | 两条证据独立：补人工那条，按 `07` A/B/C 目视逐条过 |
| 只修 CRITICAL，WARN 累积到交付后返工 | WARN 没建账 | WARN 逐条登记，保留的写明文简背书，未登记的当未处理 |
| 把方向特性当缺陷 | 拿另一方向的标准评（用 Swiss 的克制评 Brutalist 的硬阴影） | 按该页面锁定的方向评；例外看有无简报原话背书 |
| "整体感觉"当结论 | 命题不可判定 | 每条必须能写成"把 X 改成 Y，判据 Z 成立"，写不出就删 |
